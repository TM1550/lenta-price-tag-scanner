## Подготовленный сценарий

`server_video_oof.py` по умолчанию создаёт только план и пять конфигов инференса.
Будущий полный запуск выполняет:

1. Свежую YOLOv8n для каждого fold: 100 эпох, imgsz 1280, batch 8, AdamW,
   параметры ранее подготовленного `train_yolo_roboflow.yaml`.
2. Для каждого видео загрузку `last.pt` только его отложенного fold.
3. Полный видеопрогон: YOLO → BoT-SORT → фильтры → top-2 кропа → Paddle CPU +
   Qwen3-VL-4B GPU → QR/каталог по точному коду → CSV. EfficientNet выключен,
   как в прежнем финальном пайплайне. Старые teacher-веса не используются.
4. Автоматическое связывание эталонных строк и OCR-кропов через историю bbox
   трекера, без использования распознанного текста для выбора пар.
5. Проверку фактического train-списка, завершения 100 эпох и SHA256 детектора,
   реально использованного видеоинференсом. Затем micro/macro OOF-агрегацию.

Проверка разделения моделей не подтверждает все автоматические связи ценников.
В будущих отчётах сохраняется `manual_identity_review_completed=false`;
неоднозначные и пропущенные эталонные поля остаются в знаменателе.
Текущий план **не содержит вычисленной OOF-метрики**.

## Окружение и ресурсы

`environment.sh` хранится в корне отдельной папки. Он направляет окружение,
кэши, tmp и модели внутрь этой папки и по умолчанию скрывает все GPU.
Никакие пакеты и настройки системы не изменяются. Используется собственная `.venv`.
План и проверку датасета можно выполнить в минимальном CPU-окружении.

На проверке GPU0 была занята соревнованием, GPU1 занята и запрещена.
На диске было около 5 GiB до переноса, после переноса осталось около 4 GiB.
Системных torch/pip нет. Полный CUDA-runtime и Qwen в доступное место не помещаются.
Тяжёлую установку скрипт начинает только при наличии **35 GiB свободного места**,
включая запас для установки и результатов. Чужие данные удалять нельзя.

Пакеты runtime закреплены по текущему `poetry.lock`. Qwen закреплён на revision
`ebb281ec70b05090aa6165b016eac8ec08e71b17`, при инференсе используются только
локальные файлы. Установка полного runtime и сквозное выполнение этого нового
серверного сценария пока не проверены. Подготовка плана не импортирует torch
и не запускает subprocess обучения/инференса.

## Команды на сервере

Подготовка и проверка плана, без GPU-вычислений:

```bash
cd /home/ozon_hack/lenta-oof-20261104/project
source ../environment.sh
bash scripts/server/prepare_env.sh
bash scripts/server/launch_oof.sh
```

План: `../artifacts/oof_plan/plan.json` и `pipeline_fold_0.yaml` … `pipeline_fold_4.yaml`.
Минимальные установленные версии: `../artifacts/requirements-prepare-installed.txt`.

Дальнейшие команды подготовлены **для отдельного последующего разрешения**,
после освобождения места и согласования свободной GPU0:

```bash
bash scripts/server/install_runtime.sh --install
bash scripts/server/launch_oof.sh --execute
```

Без `--install` скрипт установки ничего не загружает. Без `--execute` launcher
создаёт только план. При `--execute` проверяется отсутствие compute-процессов
GPU0, VRAM <=512 MiB и загрузка <=5%; при занятой карте запуск завершается.
GPU1 никогда не выбирается. Отдельного MLflow HTTP-сервиса не создаётся:
логирование идёт в локальный SQLite `../artifacts/mlflow.db`, UI можно поднять
отдельно на согласованном порту. Перед значимым запуском следует сохранить
версию кода в Git; переданный snapshot также описан пофайловым SHA256-манифестом.

Будущие результаты: `../results/video_oof_v1/training`, `fold_N/pipeline`,
`fold_N/evaluation`, `oof_provenance.json`, `submission_oof.csv`, общий `report.json`.
Повторный запуск использует новый output, существующие эксперименты не перезаписываются.
