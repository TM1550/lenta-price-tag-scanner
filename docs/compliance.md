## Замечания к воспроизводимости и коду

1. **Передать доступ к актуальному DVC store.** После чистого клонирования
   подготовленных данных и моделей нет. Функция public-download получает
   только оригиналы организаторов. Нужен доступный проверяющему remote или
   полный актуальный архив object store с проверенной инструкцией восстановления.
   Старый `coursework_artifacts.tar.gz` из README сам по себе не доказывает,
   что включает новый набор и итоговый snapshot от 04.11.
2. **Зафиксировать версию исходников до обучения.** Серверный проект копировался
   без `.git`, поэтому `data_loader.code_version()` вернул `uncommitted`.
   Шесть runs подтверждают этот результат. Для будущих запусков надо передавать
   реальный source commit и отдельно dirty/source-tree SHA256. Для исторического
   запуска следует сохранить настоящую опись и пояснение, а не подменять прошлое
   значение фиктивным «чистым» коммитом. Экспортировать MLflow DB + artifacts
   тоже нужно: автоматический перенос результатов не включал сам журнал MLflow.
3. **Явно связать train и infer.** `configs/video_to_csv.yaml` по умолчанию
   использует `data/inference_assets/price_tag.pt`. Новый `train-yolo` сохраняет
   `runs/<name>/fold_N/training/weights/last.pt`; автоматически этот путь в infer
   не попадает. README должен показывать явный `yolo_weights=...`. Это не ошибка
   уже выполненного OOF: там checkpoint каждого fold передан правильно.
4. **Убрать буквальные нарушения правил имён.** Например:
   `annotation_frames.py:131` — `v`; `clean_yolo_labels.py:36` — `x/y`,
   `:210` — `r`, `:217–219` — `b`; `evaluate_tracks.py:64` — `v`, `:201` — `p`,
   `:336` — `h/w`; `yolo_folds.py:29` — `x/y`.
5. **Довести конфигурацию порогов.** В `field_extraction.crop_fields()` остались
   0.43 для региона имени, HSV-пороги 70/15/165/40 и доля 0.20; в некоторых
   серверных проверках число эпох зафиксировано литералом 100. Параметры,
   которые предполагается подбирать, нужно вынести в Hydra; неизменные
   семантические константы — именовать и вынести отдельно согласно заданию.
6. **Актуализировать материалы сдачи.** `docs/proposal.md/pdf` и часть README
   ещё описывают старый набор, 4 folds или отсутствие окончательной метрики;
   журналы `plots/video_oof_progress` и `plots/server_oof_runtime` — исторические
   снимки. Нужна одна актуальная сводка с новым набором, пятью folds, 4.1610%,
   ограничениями метрики и командой применения новых весов.

Пример явного применения нового checkpoint после соответствующего обучения:

```bash
poetry run price-scanner infer \
  yolo_weights=runs/yolo_roboflow_5fold_full/fold_0/training/weights/last.pt \
  videos=/absolute/path/to/new_videos \
  output=data/new_video_result
```

Для OOF нельзя подставлять один fold всем пяти видео: нужно соблюдать
`data/video_oof_20261104/model_by_video.json`. Для production на новых видео
отдельно выбирается и документируется итоговая модель; OOF-набор моделей сам
по себе не является обучением одной финальной модели на всех доступных видео.

## Соответствие первоначальной заявке и качество оценки

- В заявке обещаны 5 folds по видео. Теперь YOLO это выполняет на новом
  SAM3/Roboflow-наборе; EfficientNet имеет отдельный 5-fold результат, но
  выключен в итоговом пайплайне из-за низкой полноты.
- Конвейер реально доходит до CSV и использует нужную модель каждого fold.
  Все пять видео оценены: micro **154/3701 = 0.0416104**, macro **0.0438962**.
  Автоматический перенос и DVC завершены, первые четыре отчёта сохранены.
- Формально 0.0416104 выше заявленного 0.04 только для реализованного scorer.
  Это не достаточное доказательство достижения бизнес-цели: связь ценников
  автоматическая и не подтверждена вручную; связано 95/274 GT-строк. В 154
  правильных ячейках 95 цветов; без цвета **59/3427 = 1.7216%**. Название
  совпало 1/274, цена по карте 21/271. Нужны проверенные пары и анализ ошибок.
- Детектор проходит разделение по видео. Однако OCR-конфигурации и фильтры
  выбирались с использованием изображений этих же пяти видео. Поэтому это
  OOF детектора с диагностикой полного пайплайна, а не полностью независимый
  test всех компонентов. Для независимой оценки нужен отдельный test либо
  подбор параметров внутри train-части каждого внешнего fold.
- Каталог содержит `fullname` и `code`; обещанное получение большинства цен,
  скидок и дат из БД не реализовано и не подтверждено. VLM распознаёт текст,
  а не связывает ценник с богатой товарной БД, которой здесь нет.
- Текущий CSV имеет 29 столбцов вместо первоначальных 18; строка соответствует
  сегменту трека, а не гарантированно уникальному физическому ценнику.

**Не смешивать критерии курса и хакатона.** На стр. 5 презентации Lenta метрика
описана как доля ценников, у которых распознано не менее 80% параметров. Это
другая метрика, не текущая micro-доля правильных ячеек. Сравнение с прежними
0.02 команды без общего scorer некорректно. Там же есть запрет ручной разметки
и требование UI; это ограничения соревнования, а не требования задания MLsysd.
Текущий курс-проект с собственной SAM3/ручной правкой не следует представлять
как строгое повторение регламента хакатона.
