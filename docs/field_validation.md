# Проверка правильности заполнения

На ноутбуке присутствуют пять пар MP4/CSV в ../data, результаты полного
видеоинференса, EfficientNet, ONNX и MLflow bundle. Переносимое DVC-хранилище
находится в ../server_results/dvc-store. Наличие файлов не означает полную
побайтовую сверку всех серверных результатов.

Публичный .dvc/config на момент проверки указывает ../lenta-artifact-store.
Настройки сокомандника не изменялись; доступность его remote не проверена.

```bash
poetry run python -m lenta_price_tag_scanner.evaluate_fields \
  --labels=../data \
  --predictions=data/video_csv_v2/pipeline_final/submission.csv \
  --output=data/video_csv_v2/field_validation.json
```

Метрика: число корректно восстановленных непустых эталонных полей / число
непустых эталонных полей. Метаданные исключены. Пропущенный ценник даёт ноль,
пустое/«нет» не приносит баллов. Сравнение строгое после нормализации регистра,
пробелов и десятичного разделителя. Названия не сравниваются нечётко.
Пары выбираются жадно по убыванию IoU, один к одному, IoU >= 0.3;
по умолчанию временные отметки должны совпадать. Это проектная метрика,
не подтверждённый официальный scorer хакатона. Лишние предсказания отражены
отдельным счётчиком, но не уменьшают долю восстановленных GT-полей.

Пробный расчёт существующего итогового CSV: 4/3701 = 0.1081%.
Это диагностический результат несовпадающих временных выборок, НЕ OOF:
лучшие кадры треков обычно не совпадают с кадрами эталона. Произвольное
расширение tolerance_ms нельзя использовать для улучшения отчётной метрики:
при движении камеры координаты становятся несопоставимыми.

Для корректного OOF требуется выполнить инференс на точных frame_timestamp
эталона, используя для каждого видео модели, обученные без этого видео.
Текущий scorer агрегирует по видео и считает micro-метрику. Необязательный
--oof_manifest принимает JSON-словарь video_stem -> {fold, train_videos,
checkpoint}; проверяет отсутствие тестового видео в train_videos. Это
декларация происхождения предсказаний, а не проверка содержимого checkpoint.
В train_videos должны входить данные всех обучаемых стадий, включая классификатор.
Существующий финальный CSV нельзя объявлять OOF с помощью одного manifest.

Генерация предсказаний по эталонным кадрам выполнена; результат и проблема
недоступных временных отметок описаны в [отчёте запуска](timestamp_oof_run.md).
Использованы YOLO checkpoint соответствующих видео; EfficientNet отключён,
как в итоговом пайплайне. YOLO имеет четыре исходных fold, EfficientNet пять:
при включении классификатора соответствие нужно определять видео,
а не равенством числовых индексов fold.
