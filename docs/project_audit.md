# Проверка проекта MLsys — 2 ноября 2026

## Итог

Пайплайны обучения работают на проверенном серверном окружении, но проект пока не готов к сдаче целиком. Проведена проверка по три эпохи на полном составе всех folds: EfficientNet — пять, YOLO — четыре. Это проверка численной и эксплуатационной устойчивости, а не достаточная тренировка или доказательство качества.

## Проверка обучения

Перед запуском GPU0 RTX 5090: 2 MiB, 0%, вычислительных процессов не было. GPU1 занята и не использовалась. Все действия — внутри /home/ozon_hack/lenta-ml-system. После завершения GPU0 снова 2 MiB. Одно наблюдение во время EfficientNet: 7028 MiB, 94%; это не измерение пикового потребления.

EfficientNet: 5 folds × 3 эпохи, размер 320, batch 32, весь соответствующий train каждого fold. Все 15 значений train_loss конечны, loss между первой и третьей эпохой уменьшился на всех folds. F1: 0.8400, 0.7937, 0.8468, 0.9556, 0.1304. Для fold4 (49_5) recall=0.0698, хотя train_loss снизился с 0.8320 до 0.0538. Это выраженная проблема переноса на отложенное видео; высокая общая accuracy на дисбалансных данных её скрывает. Метрики измеряют согласие с учителем, а не ручную оценку читаемости текста. Не выбирать порог по outer fold; калибровку и подбор выполнять внутри training groups.

YOLO: 4 folds × 3 эпохи, размер 1280, batch 8, весь train. Все loss конечны и снижаются, ошибок CUDA/OOM нет. mAP50 по folds: 3.48e-7, 0, 6.86e-6, 0. Три эпохи с нуля на 251 изображении не дали пригодного детектора. Следующий отдельный эксперимент — согласованное более длительное обучение или независимые pretrained веса общего назначения; старый price_tag.pt нельзя использовать для честной OOF, если он видел эти видео. Конфиги текущего проекта без согласования не изменялись на новый метод.

Модели, OOF predictions, history CSV и metrics.json сохранены на сервере в project/runs/stability*efficient и project/runs/stability_yolo. Логи в logs/stability*\*.log; машинный отчёт — logs/stability_report.json. Нули val-loss в ранних эпохах YOLO означают пропущенную валидацию, а не идеальное качество: val=False, Ultralytics всё равно делает завершающую оценку. Использована последняя модель, без выбора лучшей по outer validation.

## Соответствие заявке пользователя

Источник: «Проект по ML System (1).docx».

- YOLO → EfficientNet реализовано; EasyOCR baseline и VLM+catalog в сдаваемый end-to-end pipeline пока не интегрированы.
- В заявке OOF 5 folds. Теперь согласованное изменение: YOLO 4 видео / 4 folds, EfficientNet 5 / 5. Заявку нужно актуализировать. У наборов разный состав видео: нельзя объединять их fold_N как будто это один сквозной end-to-end split.
- В заявке выходной CSV с 18 полями; хакатон дополнительно требует QR-поля. Нужно утвердить и реализовать схему и правило «нет»/пусто, а также одну строку на уникальный ценник. Новый инференс пока выдаёт наблюдения, без трекинга.
- Цель >0.04 по конечной метрике не измерялась. F1 EfficientNet или mAP YOLO не заменяют эту метрику. Нужен проверенный scorer полей/товаров по исходным CSV.
- VLM с базой технически возможна, но локальный db_hack.csv содержит только fullname/code: из него нельзя восстановить большинство остальных полей. Подробности в ocr_vlm_research.md.
- Сервис Triton заявлен, но отсутствует. Для него понадобятся конфигурация моделей, веса, runtime/backend и orchestration препроцессинга; тезис «дополнительные компоненты не нужны» нужно уточнить.
