# Привязка эталонных ценников к OCR через треки

Реализован прототип оценки по видео. В качестве связующего слоя используется
история bbox YOLO с идентификаторами сегментов треков. Текст OCR, названия,
цены и штрихкоды не участвуют в выборе соответствия.

```text
CSV организаторов: время + bbox
             ↓ ближайший наблюдаемый кадр, IoU
       сегмент трека на видео
             ↑ ближайший наблюдаемый кадр, IoU
CSV пайплайна ← выбранный OCR-кроп: номер кадра + bbox
             ↓
       сравнение полей двух строк
```

У одного сегмента есть bbox на многих кадрах. Поэтому время лучшего OCR-кропа
может отличаться от времени эталонной строки. Числовые track ID разных запусков
не приравниваются: оба набора якорей независимо привязываются к одной истории
детекций. Все ключи треков включают видео.

## Алгоритм и ограничения

1. Из MP4 последовательно читаются реальные PTS кадров. Для старых результатов
   время восстанавливается по `frame_index`: формула frame/fps для VFR непригодна.
2. Для эталонной строки выбирается ближайший кадр истории треков в пределах
   100 мс. Среди bbox только этого кадра ищется IoU >= 0,5. Поиск лучшего IoU
   по всему временному окну не выполняется. Время вне доступного видео
   не заменяется последним кадром.
3. Если разрыв между двумя подходящими кандидатами меньше 0,1 IoU, связь
   остаётся неоднозначной. Если один сегмент связан с несколькими эталонными
   строками, требуется проверка: возможны повторная разметка или ID switch.
4. Строки результата CSV привязываются через `details.jsonl` и `tracks.json`
   к исходным OCR-кропам. Проверяются порядок/содержимое строк CSV, bbox и
   происхождение кропов. Затем кроп связывается с общей историей треков.
5. Если несколько строк CSV попали в один сегмент, выбирается строка с лучшим
   quality rank, затем IoU, затем индексом строки. Правильность текста не влияет
   на выбор. Один результат не получает баллы за несколько эталонных строк.

Трекер не гарантирует физическую идентичность ценника. Основной пайплайн делит
треки при разрывах, геометрических скачках и превышении 10 секунд. Сегменты
не склеиваются по одинаковому OCR-тексту. Фрагментация может уменьшить число
найденных связей, а ID switch — создать ошибочную связь. Галерея предназначена
для ручной проверки автоматических соответствий.

Новые прогоны видео сохраняют в `filter_audit.jsonl` реальный PTS,
`tracker_id` исходного трекера и `track_id` ограниченного сегмента. В
`details.jsonl` добавлен `csv_row_index` с нуля; формат submission CSV сохранён.

## Выполненная проверка

На CPU выполнен новый YOLO + BoT-SORT прогон полного `43_15.mp4`: 45 сегментов.
Распознанный текст взят из сохранённого `data/video_csv_v2/pipeline_final`,
новый OCR/Qwen-прогон не выполнялся. Через новую историю треков связаны
27 из 29 эталонных строк, 54 выбранных кропа; 51/395 правильных полей (12,91%).
Два эталонных bbox не получили подходящего совпадения на ближайшем кадре.

На всех пяти видео повторно использована сохранённая история детекций;
реальные PTS восстановлены из видео по номерам кадров. Новый YOLO-прогон
всех пяти видео на этом этапе не выполнялся.

| Видео     | Правильных / ожидаемых полей |      Доля |
| --------- | ---------------------------: | --------: |
| 25_12-20  |                     41 / 745 |     5,50% |
| 25_2-10   |                     20 / 775 |     2,58% |
| 26_12-20  |                    63 / 1001 |     6,29% |
| 43_15     |                     51 / 395 |    12,91% |
| 49_5      |                     25 / 785 |     3,18% |
| Все видео |               **200 / 3701** | **5,40%** |

Связано 123/274 эталонных строк и 246 выбранных кропов. Из остальных строк
137 не имеют геометрического совпадения, 8 относятся к двум недоступным
временным отметкам, 6 попали в сегменты с несколькими эталонными якорями.
Все их непустые эталонные поля сохранены в знаменателе и дают ноль.

Из 200 совпадений 116 приходятся на цвет, 58 на скидку, 25 на цену по карте
и одно на название. В отчёте есть также группы `without_color` и
`printed_prices`, чтобы цвет не скрывал качество распознавания текста.
Метаданные не оцениваются. Пустые значения и «нет» эталона исключены,
как в прежнем scorer; присутствие, отсутствие и неизвестность полей пока
не разделены отдельной ручной разметкой.

Это **диагностическая оценка автоматических связей**, не официальный scorer
хакатона и не независимая OOF-оценка. Использована старая YOLO; новые пять
OOF-моделей ещё не обучены. 5,40% не доказывают достижение проектной цели.
Оставшиеся 307 предсказанных строк отдельно перечислены как не выбранные;
неполный GT не позволяет объявить их все ложными срабатываниями.

## Результаты

Каталоги: `data/track_association_43_15_v1` и `data/track_association_all_v1`.

- `review.html`: пары GT-кроп / кроп исходной строки CSV и значения полей.
- `gt_to_prediction.csv`: видео, эталонная строка, reference track, кадры,
  IoU, индекс строки результата, pipeline track и число правильных полей.
- `crop_to_reference.csv`: все выбранные кропы reference-прогона, предложенный
  GT ID и признак `manual_reviewed=false`. Это кандидаты связей для проверки,
  их нельзя автоматически объявлять подтверждённой OCR-разметкой.
- `prediction_to_track.json`: связи всех строк результата с reference-треками.
- `field_comparison.csv`: каждое непустое эталонное поле, предсказание и результат.
- `frame_times.json`, `report.json`, `verification.json`: PTS, метрики,
  статусы, хеши исходников и проверки подсчёта.

## Команды из корня репозитория

Новый CPU-прогон трекера на одном видео (каждый `output` должен быть новым):

```powershell
$py = '../.venv-pseudolabel/Scripts/python.exe'
$env:YOLO_CONFIG_DIR = "$PWD/data/laptop_runtime/ultralytics"
& $py -m lenta_price_tag_scanner.video_to_csv --config-name laptop_cpu pull_dvc=false detection_only=true pattern=43_15.mp4 top_k=2 output=data/my_reference_tracks
```

Привязка существующего CSV к новым трекам:

```powershell
& $py -m lenta_price_tag_scanner.commands track-eval pattern=43_15.mp4 tracking_run=data/my_reference_tracks prediction_run=data/video_csv_v2/pipeline_final output=data/my_track_evaluation
```

Воспроизведение диагностики пяти видео по сохранённой истории:

```powershell
& $py -m lenta_price_tag_scanner.commands track-eval output=data/my_all_track_evaluation
```

Нужны локальные исходные видео/CSV и полный каталог результата пайплайна,
включая crops, tracks, details и filter_audit. История старого прогона хранится
в серверном резервном DVC-архиве; одного `submission.csv` недостаточно для
проверяемой связи с исходными кропами и исправления старых временных отметок.

Для настоящего OOF нужно получить отдельный полный видеопрогон каждой
отложенной модели на своём видео, затем выполнить сопоставление на результатах
этих прогонов. В текущем прототипе `oof=false` фиксируется явно. Ручная проверка
соответствий и исправление ошибочных GT-якорей остаются необходимыми.
