# Автоматический перенос завершённого OOF

**04.11.2026 в 21:19 Asia/Novosibirsk перенос успешно завершился.**
Все пять результатов получены, DVC обновлён и проверен, процесс остановился.
Общая правильность ячеек — 154/3701 = 4,1610%.
[Итоговые результаты и ограничения](video_oof_results.md).

Для переноса на ноутбуке был запущен одноразовый фоновый процесс
`../server_results/tools/auto_transfer_completed_oof.py`.
Он проверяет сервер раз в 30 секунд и ждёт не более 24 часов.
Оценку и обучение он не запускает, GPU не использует.

Условия переноса: серверный статус `completed`, готовы все пять evaluation
и общий `report.json`. Затем процесс:

1. На сервере независимо пересчитывает число правильных ячеек по CSV,
   проверяет пять checkpoint, 100 эпох и отсутствие отложенного видео в train.
2. Упаковывает модели, пять отчётов, общий CSV, кропы и HTML для проверки связей,
   конфиги, графики и журнал происхождения. Qwen, исходные видео и кеши не скачивает.
3. Скачивает архив, проверяет его SHA256 и каждый файл по манифесту.
4. Добавляет результаты в `data/video_oof_20261104`. Изменённые пользователем
   файлы не перезаписывает. Старые промежуточные метаданные сохраняет в
   `../server_results/oof_server_20261104/pre_final_metadata`.
5. Обновляет `data/video_oof_20261104.dvc`, выполняет push и pull только в
   локальный remote `laptop-temp`, затем проверяет MD5 всех объектов снимка.
6. Записывает `completion.json` и останавливается. Git commit/push не выполняет.

Статус и журнал:

- `../server_results/oof_server_20261104/auto_transfer/status.json`;
- `../server_results/oof_server_20261104/auto_transfer/transfer.log`;
- `../server_results/oof_server_20261104/auto_transfer/completion.json` после успеха;
- `data/video_oof_20261104/review.html` — итоговая таблица и галереи пяти видео.

Ошибки подключения и переноса повторяются автоматически в пределах 24 часов.
Если серверная оценка завершилась ошибкой, процесс останавливается со статусом
`remote_stopped`; неполный набор не объявляется итоговым.
Два процесса переноса одновременно не допускаются файловой блокировкой.

Ноутбук должен быть включён и иметь доступ к серверу через существующий SSH/NetBird.
Сон приостанавливает локальную работу; после пробуждения проверка продолжится,
если не истёк лимит ожидания. После перезагрузки нужно запустить процесс заново.
Пароли в скриптах не хранятся; используется существующая SSH-конфигурация.

Повторный запуск из PowerShell, из папки `MLOPS_codex`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\server_results\tools\start_oof_auto_transfer.ps1
Get-Content .\server_results\oof_server_20261104\auto_transfer\status.json
```

`laptop-temp` находится на том же ноутбуке и не заменяет внешний DVC remote.
Автоматические связи ценников остаются без ручного подтверждения; метрика
не является официальным scorer хакатона.
