# Распознавание ценников на видео торгового зала

Автор: **Цыренов Мэргэн**. Версия: **05.11.2026**.

## Постановка задачи

Система извлекает структурированные сведения с ценников по видео движения
робота вдоль торговых полок. Обнаружение ценников, объединение наблюдений,
выбор читаемых изображений и распознавание текста выполняются единым
пайплайном. Результат предназначен для цифрового мониторинга торгового зала.
Постановка и реальные исходные материалы предоставлены организаторами
[хакатона Lenta Tech](https://drive.google.com/drive/folders/1_UbQ7x4MK9fZjA-9DqJY_A8nedsg9KMy).

## Формат входных и выходных данных

Вход - каталог MP4-видео, включая записи в разрешении 4K. Поворот кадров,
размер изображения и шаг обработки задаются конфигурацией. Детектор выделяет
ценники, трекер объединяет наблюдения, затем выполняются отбор кропов и OCR.

Выход - `submission.csv` в UTF-8 BOM с 29 столбцами: 18 основных и 11
дополнительных QR-полей. Таблица содержит наименование, ценовые поля, коды,
имя видео, временную отметку в миллисекундах и bbox в пикселях исходного кадра.
Пустая ячейка обозначает отсутствие достоверно извлечённого значения.
Строка соответствует сегменту трека; один физический ценник может иметь
несколько сегментов. [Схема CSV и артефакты инференса](video_to_csv.md).

## Метрики

Основная метрика проекта - доля правильно заполненных содержательных полей:
число совпавших с эталоном значений делится на число доступных эталонных полей.
Пропущенные соответствия остаются в знаменателе. Micro рассчитывается по
суммарным счётчикам, macro - как среднее по видео. Предсказания сопоставляются
с эталонными CSV автоматически по видео, времени и bbox.
[Методика сопоставления](track_evaluation.md).

Полный OOF-пайплайн с EfficientNet rank, PaddleOCR и Qwen3-VL получил
**152/3701 = 4.1070% micro**, **4.3018% macro** на пяти видео. Исторический
запуск без EfficientNet получил 154/3701 = 4.1610%. Улучшение новым запуском
не подтверждено; сравнение не является изолированным экспериментом одного
изменения. Ориентир первоначальной заявки - доля более 0.04. Используемый
протокол является метрикой проекта и отличается от официального scorer
хакатона и простой заполненности CSV.
[Результаты и счётчики по видео](efficient_video_oof_results.md).

Компоненты оцениваются отдельно: YOLO - mAP и precision/recall;
EfficientNet - precision 0.8645, recall 0.5286, F1 0.6560 на 2008 OOF-кропах;
Qwen OCR - CER 0.5869 на 294 транскрипциях. OCR-сравнение выполнено на
development-выборке и не выдаётся за оценку на независимом тесте.
[Классификация кропов](efficient_review.md), [сравнение OCR](ocr_inference.md).

## Валидация

Для YOLO и EfficientNet применяется OOF из пяти folds с группировкой по видео:
изображения одного видео не распределяются между обучающей и отложенной
частями. Каждая модель обучается независимо. YOLO обучены по 100 эпох,
используется `last.pt`; EfficientNet - по 10 эпох. Внешний fold не используется
для выбора лучшего checkpoint. Исходная версия YOLO с четырьмя видео
сохранена отдельно. [Разбиение YOLO](yolo_roboflow_oof.md),
[команды OOF-обучения](oof_training.md).

При полной видеооценке для каждого видео загружаются соответствующие
отложенные YOLO и EfficientNet. SHA256 весов и train-списков YOLO проверены.
Старые EfficientNet-checkpoints не содержат train-manifest: принадлежность
fold восстановлена по детерминированному разбиению, а held-out предсказания
сверены с текущими метками и SHA256 изображений. Автоматические соответствия
ценников вручную не проверялись. Эти ограничения относятся к интерпретации
[полного OOF-результата](efficient_video_oof_results.md).

## Данные

Основной набор содержит пять реальных видео и эталонные CSV организаторов.

Хранилище - закрытый MinIO-бакет `s3://lenta-dvc` с HTTPS endpoint
`https://31.31.207.108`. Пользователю выдаются S3-ключи на чтение;
SSH-доступ для загрузки не требуется. Ключи хранятся только в локальной
конфигурации или переменных окружения. Данные и веса исключены из Git.
[Состав DVC-артефактов и настройка доступа](dvc_handoff.md).

CPU-профиль использует локальные PaddleOCR-веса из DVC и выполняется без Qwen.

[CPU-профиль](laptop_run.md).

## Моделирование

### Бейзлайн

[YOLOv8](https://docs.ultralytics.com/) обнаруживает ценники,
[EfficientNet-B0/timm](https://huggingface.co/docs/timm/) оценивает пригодность
изображения для распознавания, [EasyOCR](https://www.jaided.ai/easyocr/)
извлекает текст. Обучение EfficientNet реализовано через
[PyTorch Lightning](https://lightning.ai/docs/pytorch/stable/), YOLO - через
Ultralytics. EasyOCR на имеющейся OCR-выборке: CER 0.7706, WER 0.9729.
[Протокол сравнения вариантов](ocr_inference.md).

### Основная модель

YOLO → BoT-SORT → геометрические и резкостные фильтры → EfficientNet rank →
top-k кропов → PaddleOCR + Qwen3-VL → QR/EAN → сопоставление с каталогом → CSV.
В измеренном OOF используются top-2, stride=3, imgsz=1280, вес ранжирования 0.5.
EfficientNet оценил 9561 кроп; вероятность читаемости влияет на ранжирование
без жёсткого порогового удаления. [Параметры полного прогона](efficient_video_oof_results.md).

[PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR) выполняет CPU-OCR,
[Qwen3-VL-4B](https://github.com/QwenLM/Qwen3-VL) используется как VLM для
дополнительного распознавания текста и наименования. Локальный каталог
содержит `fullname` и `code`: подтверждённое совпадение кода позволяет уточнить
название. Большинство ценовых полей из каталога не восстанавливается.
Неоднозначные совпадения сохраняются как предложения.
[Извлечение полей](video_to_csv.md).

## Внедрение

Публичный репозиторий -
[TM1550/lenta-price-tag-scanner](https://github.com/TM1550/lenta-price-tag-scanner),
сдаваемая ветка - `main`. Пакет `lenta_price_tag_scanner` устанавливается через
Poetry с lock-файлом. Click предоставляет команды, Hydra - иерархические
YAML-конфигурации. DVC pull встроен в train, infer, export и упаковку сервисов.
Обучение и инференс разделены; зависимости обучения и VLM вынесены в группы.
[Инструкции Setup, Train, Production preparation и Infer](../README.md).

EfficientNet и YOLO экспортируются в ONNX; проверяются ONNX checker и
согласованность с PyTorch. MLflow Serving предоставляет HTTP `/invocations`
для классификатора кропов и детектора. Полное видео обрабатывается отдельной
batch-командой. TensorRT и Triton не входят в подтверждённую поставку.
[YOLO ONNX и HTTP-сервис](yolo_deployment.md),
[MLflow PythonModel](https://mlflow.org/docs/latest/ml/model/python_model/).

### Воспроизводимость и инженерная проверка

MLflow записывает гиперпараметры, loss, метрики, Git commit, dirty-флаг,
конфигурации и графики. Адрес по умолчанию - `http://127.0.0.1:8080`.
Короткие CPU-обучения обеих моделей по две эпохи завершились четырьмя
FINISHED runs; сохранены 17 графиков и журналы в `plots/`.
[Протокол обучения и MLflow](training_control.md).

Чистая установка полного окружения на Linux/Python 3.12 заняла 4 мин 48 с;
pip check и сборка wheel/sdist успешны. Короткий CPU-инференс семи кадров
сформировал 8 строк и 29 столбцов CSV примерно за 19 с. Текущий набор включает
61 unit-тест; обязательные pre-commit hooks проверяют Python, YAML и документацию.
Проверено наличие объектов всех девяти DVC-наборов и скачивание отдельного
файла с проверкой TLS в пустой cache. Полное повторное скачивание девяти наборов
после миграции не выполнялось. [Аудит соответствия](compliance.md).

### Ограничения

Низкое разрешение ценников, размытие, ошибки временной привязки и фрагментация
треков ограничивают качество. Часть старых MLflow runs не содержит Git commit;
их версия подтверждена SHA256-описью исходников. Новые контрольные runs
логируют точный commit. Qwen требует больше ресурсов, чем CPU-профиль;
полные веса этой модели в DVC не включены. Согласованные ограничения оценки
и фактические результаты описаны в [OOF-отчёте](efficient_video_oof_results.md)
и [описании локального запуска](laptop_run.md).
