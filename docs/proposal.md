# Распознавание ценников из видео

## Постановка задачи

Извлечение структурированных данных с ценников из видео торгового зала. Вход: MP4, в том числе 4K. Выход: CSV по сегментам треков с названием, ценовыми полями, кодами и другими доступными атрибутами. Автор: Цыренов Мэргэн.

## Формат входных и выходных данных

Видео обрабатывается с настраиваемым шагом. Детектор выдаёт области ценников, трекер объединяет наблюдения во времени, фильтры выбирают читаемые кропы. Текущий CSV: 29 столбцов — 18 основных и 11 дополнительных. Сегмент трека не гарантирует уникальность физического ценника. Полные исходные видео и персональные настройки доступа не включаются в Git.

## Метрики

Целевая бизнес-метрика из первоначальной заявки: доля правильно найденных полей более 0,04 (ориентир хакатона 0,02). Для её измерения нужны эталонные поля и сопоставление ценников. Сейчас измерены заполненность CSV, OCR CER/WER и OOF-метрики моделей. Заполненность 916/9890 = 9,26188% на пяти видео НЕ доказывает достижение бизнес-цели. Для YOLO используются mAP/precision/recall, для EfficientNet — precision/recall/F1, для OCR — CER/WER.

## Валидация

YOLO: 4 folds с разделением по четырём исходным видео, согласно согласованному изменению. EfficientNet: 5 folds по видео, без смешивания кадров одного видео между train и validation. После ручной переразметки создан отдельный снимок 2008 кропов; конфликтные ключи исключены. OCR: 294 размеченные пары, пять видео; выбор варианта на этом же наборе делает оценку оптимистичной. Для финальной приёмки нужен независимый набор.

## Данные

Исходная YOLO-разметка содержит 251 кадр и 2118 рамок; EfficientNet — 350 положительных и 1658 отрицательных кропов. OCR-данные предоставлены пользователем. Данные и проверочные веса описаны DVC. Подготовлено переносимое хранилище; его публичный URL или remote ещё должен предоставить владелец. Публичные исходники Google Drive не заменяют актуальную ручную разметку и manifests.

## Бейзлайн

YOLOv8 для ценников, EfficientNet для пригодности кропов, EasyOCR для текста. EasyOCR на имеющейся OCR-разметке: CER 0,770587, WER 0,972879. EfficientNet OOF после переразметки: precision 0,864486, recall 0,528571, F1 0,656028. Из-за низкой полноты классификатор отключён по умолчанию в итоговом видеоинференсе.

## Основная модель и решение

YOLO → BoT-SORT → ограниченные по времени сегменты → геометрические/резкостные фильтры → top-k кропов → PaddleOCR CPU для текста и цен + Qwen3-VL-4B-Instruct для названия → QR/EAN и точный поиск в каталоге → CSV. Сравнены восемь OCR-конфигураций; Qwen baseline имеет CER 0,586948 и WER 0,726145. VLM может ошибаться и не заполняет неизвестные поля произвольными значениями. Каталог используется только при совпадении кода; обещанное в первоначальной заявке восстановление большинства полей через БД не подтверждено.

## Внедрение и воспроизводимость

Устанавливаемый пакет lenta_price_tag_scanner, команды Click с Hydra, Poetry lock, отдельные группы зависимостей, DVC pull при train/infer. Lightning используется для EfficientNet, Ultralytics — для YOLO. MLflow хранит параметры, loss, метрики, commit/dirty и графики. Созданы ONNX EfficientNet с проверкой PyTorch/ONNX Runtime и MLflow HTTP-сервис классификации кропов. TensorRT/Triton остаются необязательным непроверенным направлением. Qwen использует GPU; CPU-вариант Paddle доступен отдельно.

## Результаты инженерной проверки

Чистая установка зависимостей и pip check успешны. 19 unit-тестов пройдены. Wheel установлен и конфигурация прочитана вне исходников. Короткое обучение на реальных данных завершилось с логированием MLflow. ONNX batch 1/2: максимальная абсолютная разница logits 9,16e-5. HTTP /invocations вернул корректную структуру вероятности. Короткий CPU-видеоинференс: 9 строк CSV, 14,98% заполненности; это проверка исполнения, не оценка качества.

## Ограничения и оставшаяся работа

Нужны независимая оценка правильности полей, публичный доступ к DVC-артефактам и публикация репозитория владельцем. Найденные в старой DVC-конфигурации учётные данные удалены из рабочего публичного файла; пароль необходимо заменить и очистить историю перед GitHub. Полные GPU-эксперименты в аудите не повторялись из-за занятой GPU 0. Изменения постановки следует раскрыть преподавателю, а не выдавать за исходные условия.
