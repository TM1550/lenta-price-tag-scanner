# Новый YOLO-датасет: кадры для ручной разметки

Подготовка на ноутбуке, из корня репозитория:

```powershell
& ../.venv-pseudolabel/Scripts/python.exe -m lenta_price_tag_scanner.annotation_frames
```

Результат: `data/yolo_annotation_v2/`. Повторный запуск требует нового `output=...`:
существующие данные не перезаписываются. Исходники — пять видео из DVC-снимка
`data/runtime_assets.dvc`. GPU, сервер и веса детектора не нужны.

Видео декодируется последовательно, время берётся из декодера, а не из CSV или
формулы frame/fps. В каждом интервале 500 мс выбирается до одного кадра: самый резкий из кандидатов
с шагом не менее 100 мс. Резкость оценивается на уменьшенной копии; сохраняется
полный кадр исходного разрешения, JPEG quality 97. Это относительный отбор:
полностью смазанные интервалы автоматически не исключаются и требуют просмотра.
Отбор не зависит от старой YOLO и сомнительных времён из эталонных CSV.
Интервалы без кандидатов пропускаются, в том числе при скачках времени в видео
и на коротком хвосте ролика. Кадры для заполнения временных разрывов не дублируются.

## Передача в разметку

- `roboflow_images.zip` содержит только изображения; можно использовать и папку `images`.
- `preview_*.jpg` — обзорные листы. Их не нужно загружать в датасет.
- `manifest.json` хранит исходное видео, индекс кадра с нуля, фактическое время,
  размер, SHA256, fold и признак `annotated=false`.
- `sources.json` содержит хеши исходных видео и число декодированных кадров.
- `folds.json` задаёт предварительное разделение по целым видео.
- `COMPLETE.txt` появляется только после успешной подготовки всего пакета.

На этом ноутбуке ZIP удалён 04.11.2026 после загрузки в Roboflow и сверки
содержимого. Все 400 исходных JPEG и манифест сохранены; для повторной загрузки
можно выбрать папку `images`. Новый запуск генератора по-прежнему создаёт ZIP.

Размечать нужно один класс `price_tag`: все видимые ценники на полном кадре.
SAM3 можно использовать как помощника, затем проверить пропуски, лишние объекты
и границы. Для текущего YOLO-пайплайна нужен итоговый экспорт **object detection**
с прямоугольниками в формате YOLO, а не только маски сегментации.
Сохраняйте исходную часть имени `video__fNNNNNNN__tNNNNNNNNNms`:
она связывает экспорт с манифестом даже при добавлении сервисного суффикса.
Не создавайте аугментированные копии до разделения на folds.

Плохой кадр можно исключить целиком. Пустая разметка допустима только после
ручной проверки, что ценников действительно нет. Не оставляйте неразмеченные
видимые ценники: при обучении они будут ошибочно считаться фоном.
Этот пакет пока **не обучающий датасет**: файлов labels и готового data.yaml нет.

## OOF после разметки

Предлагается пять folds, по одному исходному видео в validation; остальные четыре
в train. Разбиение Roboflow по случайным кадрам для оценки не использовать.
После экспорта нужно сопоставить изображения с манифестом, проверить метки,
исключённые кадры и собрать пять YOLO data.yaml. Folds пересобираются из реально
размеченных кадров; каждый fold должен остаться непустым.

Раньше оригинальная разметка покрывала четыре видео, включая `26_2-10`, для которого
здесь нет исходного видео. Новый пакет содержит `25_12-20`, `25_2-10`, `26_12-20`,
`43_15`, `49_5`; старые изображения автоматически не добавляются.
Пять видео — только пять групп, размеры folds будут неравными. Если разные видео
снимают одну полку/одни ценники, следует объединить их в одну группу: тогда честных
folds будет меньше пяти. Каждая модель должна обучаться заново на своём train;
старые веса, обученные на этих видео, нельзя использовать как независимую OOF-модель.
