# Валидация по эталонным временным отметкам, 03.11.2026

Исходные CSV сохранены эталоном. Псевдометки старой YOLO не подменяют
ручную разметку и не превращают оценку согласия с учителем в OOF.

Найдена причина остановки: две временные отметки выходят за доступные PTS:

| Видео    | Последний декодированный кадр, мс | Отметка CSV, мс |
| -------- | --------------------------------: | --------------: |
| 25_12-20 |                         41163.507 |           41738 |
| 25_2-10  |                         30408.773 |           31771 |

Последовательное чтение декодирует соответственно 823 и 609 кадров без
провала внутри потока. Локальные копии имеют те же размеры, что серверные.
Это не подтверждает побайтовую идентичность, но замена одним локальным файлом
без проверки не обоснована. Недоступные строки сохраняются в знаменателе
как пропущенные поля; последний кадр не используется вместо отсутствующего.

В scripts/validate_timestamp_oof.py реализовано последовательное декодирование
по PTS вместо перемотки через средний FPS. Выбирается ближайший реальный кадр
с допуском 100 мс, фактическое время пишется в frame_audit. Пропуски явно
фиксируются в unavailable_timestamps. Для сопоставления CSV используется
исходная запрошенная временная отметка; геометрия берётся только из детектора.

Fold определяется по видео из folds.json, а не по совпадению числовых индексов.
Используется last.pt после фиксированных трёх эпох, не best.pt. EfficientNet
отключён, как в итоговом пайплайне. Из пяти видео три имеют соответствующий
YOLO OOF-fold; два отсутствуют в обучении YOLO и оцениваются отдельно как
external_holdout с заранее выбранным fold 0. Четвёртое исходное YOLO-видео
26_2-10 отсутствует среди предоставленных видео/CSV.

Первый завершившийся CPU-запуск: OOF 0/2141, external_holdout 0/1560.
Причина: ни одной детекции при conf=0.25 у моделей, обученных с нуля три эпохи.
Это реальный провал модели, не повод менять эталон или подбирать порог по test.
OCR и Qwen не получили кропов. GPU 0 была занята на 96–99%; GPU 1 не использована.

После восстановления SSH 03.11.2026 подтверждено: повторный запуск с новым
декодером завершился. Итог тот же: OOF 0/2141, holdout 0/1560; детекций нет.
Обработана 61 временная отметка, две недоступны и сохранены в знаменателе.
Результаты перенесены в server_results/server_project_final_20261103/outputs/timestamp_oof
рядом с рабочим репозиторием и включены в резервный DVC-архив.
Четыре локальных теста scorer проходят: нормализация цены,
пропущенная детекция, запрет двойного сопоставления, несовпадение времени.
