# Подготовка датасета и план сдачи

## Что требуется

По «Домашнее задание MLsysd (2).pdf» нужен воспроизводимый Python-пакет: загрузка данных через DVC, preprocessing, обучение, инференс, Poetry/uv с lock-файлом, pre-commit, Hydra, MLflow (минимум три графика, параметры и git commit). ONNX, TensorRT и сервер инференса дают дополнительные баллы. README должен включать описание проекта и рабочие команды Setup / Train / Production preparation / Infer. Название репозитория должно отражать задачу: текущий Design_ML_system следует переименовать перед сдачей. Самостоятельно репозиторий не переименован.

По заявке «Проект по ML System (1).docx»: YOLO → EfficientNet → EasyOCR; затем сравнение с вариантом VLM и базой товаров. Цель метрики >0.04 против заявленного результата хакатона 0.02. Пять folds должны соответствовать пяти видео, а не случайным кропам. Совпадающие товары/сцены между видео дополнительно требуют проверки утечки.

По презентации Lenta: строка CSV соответствует уникальному ценнику, требуются 18 основных полей и дополнительные QR-поля; timestamp в миллисекундах. Отсутствующее поле обозначается «нет», нераспознанное — пустой строкой. Это надо согласовать с оценщиком; старый код оставляет пустые поля и фиксирует цвет red.

## Что уже есть и что осталось

В сдаваемом репозитории есть заготовки YOLO training/inference/export, Hydra и MLflow. Это ещё не проверенный end-to-end pipeline. Загрузчик DVC сейчас не скачивает данные, а лишь проверяет репозиторий. В data/data.yaml пути ../train/images относительно самого yaml не соответствуют фактическому расположению data/train/images; при переносе нужно исправить пути. Конфиг сдаваемого проекта ожидает другой каталог data/price_tags.

Порядок дальнейшей работы:

1. Получить кандидаты, проверить семантику старого EfficientNet на ручной выборке.
2. Разметить пригодность кропа для OCR: читаемый ценник / непригодный кроп. Включить размытые, обрезанные и ложные детекции. CSV с полями товара не является готовой разметкой качества кропов.
3. Подготовить датасет только из вручную проверенных примеров, разделить по видео; отдельно проверить происхождение обучающих данных старых моделей. Предобученный учитель, видевший тестовые видео, не обеспечивает честную OOF-оценку.
4. Реализовать обучение EfficientNet, grouped OOF, precision/recall/F1 и итоговую метрику извлечения полей; сравнить с YOLO без фильтра.
5. Доработать DVC, обучение, MLflow, экспорт и конечный CSV; выполнить чистую установку, pre-commit и запуск по README.

## Запуск подготовки

Из Design_ML_system, в окружении Python с Poetry:

```powershell
poetry lock
poetry install
poetry run python -m lenta_price_tag_scanner.prepare_crops max_frames=150 output=data/crops_smoke
poetry run python -m lenta_price_tag_scanner.prepare_crops
```

Добавлена зависимость timm. Lock-файл необходимо обновить командой выше: в текущей среде ML-зависимости отсутствуют, lock не регенерирован. max_frames ограничивает первые исходные кадры каждого видео, 0 означает всё видео. Для GPU: device=cuda. Все относительные пути в crops.yaml считаются от корня репозитория. Повторный запуск требует нового output, существующий каталог не перезаписывается.

Без учителя:

```powershell
poetry run python -m lenta_price_tag_scanner.prepare_crops efficient_weights=null output=data/crops_unscored
```

Файлы сохраняются в positive / negative / review, внутри — каталог видео. Эти папки являются предложениями модели, а не готовыми классами для ImageFolder. manifest.jsonl содержит label=null и reviewed=false: заполните label (1 — пригоден, 0 — непригоден) и reviewed после ручной проверки. Для обучения использовать только reviewed=true; неопределённые примеры пока исключить. Fold привязан к позиции видео в отсортированном списке: при добавлении видео создайте новую версию датасета и зафиксируйте manifest.

Учитель повторяет старую реализацию: timm efficientnet_b0, один logit, 320×320, ImageNet normalization, BGR и 1-sigmoid. Семантика этих весов установлена по использованию в старом коде, исходное обучение не найдено; пригодность для OCR требует ручной проверки. legacy_bgr=false переключает RGB, invert_probability=false меняет смысл оценки. Без проверки менять их нельзя.

Отбор: шаг кадров stride=15, YOLO confidence=0.25, минимальная сторона 24 пикселя, удаление точных повторов внутри видео. Близкие кадры не дедуплицируются: это базовая версия, без трекинга. Резкость записывается для анализа, но автоматически не исключает сложные отрицательные примеры. Пороги 0.2/0.8 — начальные, не откалиброванные. Положительные и отрицательные предложения сохраняются вместе с сомнительными, чтобы не терять ошибки учителя.

config.yaml, summary.json и manifest.jsonl сохраняются рядом с кропами. Данные и веса не коммитить; после проверки версионировать через DVC. Полный запуск на видео и качество весов в текущей среде не проверены; выполнены синтаксическая проверка и проверки порогов.
