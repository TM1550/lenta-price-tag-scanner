# Лёгкий OCR-пайплайн

Выбран вариант EasyOCR RU/EN на CPU + ZXing-C++ + локальный SQLite-каталог. Он развивает OCR/QR/catalog-подход из [LinaDugau/LentaTech](https://github.com/LinaDugau/LentaTech), но не копирует его код, LLM или ценовые эвристики расширенного каталога. VLM не загружается. CPU-режим поддерживается [EasyOCR](https://jaided.ai/easyocr/documentation/); декодер использует [ZXing-C++](https://pypi.org/project/zxing-cpp/).

## Запуск

Из Design_ML_system, Python 3.12:

```powershell
poetry install --with ocr
poetry run python -m lenta_price_tag_scanner.cpu_ocr
```

По умолчанию читается data/ocr_ready/ocr_inputs.jsonl, обрабатывается по пять кропов на видео. Для всего набора:

```powershell
poetry run python -m lenta_price_tag_scanner.cpu_ocr per_video=0 output=data/cpu_ocr_all
```

Если папка результата уже существует, выбрать новый output. Для новых видео сначала запустить ocr_crops по docs/ocr_inference.md, затем передать inputs=<каталог>/ocr_inputs.jsonl. Классификатор и детектор остаются существующими; CPU-режим относится к новому этапу чтения текста.

Первый запуск скачивает веса EasyOCR в models/easyocr и строит SQLite-индекс data/catalogue.sqlite по ../data/db_hack.csv. Кэш пользовательских сетей тоже направлен в models/easyocr/user_network. При изменении CSV выбрать новый catalogue_db; индекс проверяет SHA-256 источника. Интернет нужен для первоначальной загрузки весов, но изображения и каталог во внешние API не отправляются. После загрузки возможен локальный запуск.

Основные настройки в configs/cpu_ocr.yaml: cpu_threads=4, gpu=False задан явно в коде, per_video, rotation_ccw=90, scale=2, max_side=1280. Поворот соответствует визуально проверенным примерам текущей камеры; для нового источника проверить направление. Для отключения шаблонной цены: prominent_price_field=null. Порог OCR 0.25, порог эвристики цены 0.7 — начальные настройки, не откалиброванные на независимой выборке.

## Логика и контракт

1. Повернуть и ограниченно увеличить кроп; сохранить исходные координаты/время из manifest.
2. Декодировать QR/штрихкод, разобрать JSON или URL query. Из QR поля сопоставляются по явным aliases; конфликтующие значения исключаются.
3. Прочитать текст EasyOCR. Сохранить все строки, координаты и confidence. Название предлагается по верхней части ценника; скидка и дата извлекаются по формату. Числа без контекста не назначаются произвольно в price_default.
4. Для красного шаблона можно предложить price_card по наиболее крупному числу и отдельным надстрочным копейкам справа. Если копейки неоднозначны или отсутствуют, значение остаётся пустым. Это эвристика, не универсальное распознавание верстки.
5. Проверить контрольную цифру GTIN. По однозначному точному коду восстановить fullname из каталога. Неоднозначный код не приводит к автоматическому выбору. Текстовый поиск SQLite FTS5 возвращает только кандидатов; они не перезаписывают распознанные поля.

Каталог содержит только fullname/code, поэтому цены, скидки и QR-поля из него не восстанавливаются. Каталоговый code трактуется как код товара/штрихкод для поиска; он не записывается в code итоговой схемы (код зоны выкладки). Код хранится строкой.

Выход:

- observations.csv: 29 полей схемы хакатона, одна строка на кроп-наблюдение;
- details.jsonl: исходный OCR, координаты/уверенности, распознанные коды, точный match, предложения каталога и время;
- summary.json: количество и время обработки, контрольные суммы;
- config.yaml: параметры новых запусков.

Это ещё не финальная таблица уникальных ценников: трекинг и межкадровая агрегация не реализованы. Пустое значение означает неизвестное; «нет» не ставится без уверенного знания, что поле отсутствует на шаблоне. Неизвлечённые поля остаются пустыми.

## Реальная проверка

На сервере CPU, четыре потока, 394 кропа: 231.42 секунды обработки (0.587 с/кроп), без начальной загрузки модели и индекса. GPU для OCR не использовалась. Первоначальная выборка 25 кропов: 12.41 с.

В полном прогоне: 317 непустых названий, 118 предложений price_card, 95 скидок. Два наблюдения дали декодированные коды и точное совпадение каталога; 176 — текстовые кандидаты. Это заполненность, а не точность. Имена часто содержат ошибки; цены проверять визуально. Итоговая бизнес-метрика по GT не рассчитывалась.

Семь unit-тестов проверяют GTIN, QR, отсутствие произвольной цены, необходимость копеек, отказ от неоднозначного каталога и пересборку ручной разметки. black/isort/flake8 новых модулей пройдены. Poetry lock обновлён, check --lock прошёл; чистая установка на ноутбуке не проводилась.
