## Данные и обучение

Исходная пользовательская папка `data/oof_v2` сохранена без изменений. Перемещение
файлов между классами не обновляет прежний manifest автоматически. Для запуска создан
согласованный снимок `data/efficient_user_20261102`: 2008 изображений, 350 положительных
и 1658 отрицательных. Относительно прежнего manifest изменились 105 меток, отсутствуют

`25_2-10.mp4/00000315_001.jpg`, `25_2-10.mp4/00000465_004.jpg`.

Неизменённые метки не считаются автоматически проверенными человеком. Их исходное
происхождение `teacher_pseudo` сохранено. Отчёт снимка — `snapshot_report.json`.
SHA256 совпадающих изображений между разными видео не найдено. Каждый fold удерживает
одно целое видео; соседние кадры не распределяются случайно между train и validation.

EfficientNet-B0 обучен с нуля (`pretrained=false`), RGB 320, batch 32, learning rate
0.001, seed 42, по 10 эпох на каждом из 5 folds. Проверка внешнего видео выполняется
после фиксированного числа эпох, без выбора checkpoint по внешнему fold.
Все 50 значений train loss конечны, ошибок CUDA/OOM нет. Уменьшение train loss
не означает хорошей переносимости: два внешних видео дают низкую полноту.

## Извлечение текста

Проверены все 294 пары; результаты и страница визуальной проверки находятся в
`data/ocr_prototype_20261102/review.html`. Для независимости от пяти примеров,
использованных при выборе запроса, отдельно приведены оставшиеся 289:

| Модель            | CER, 294 | WER, 294 | CER, остальные 289 | Время обработки 294 |
| ----------------- | -------: | -------: | -----------------: | ------------------: |
| EasyOCR CPU       |   0.7706 |   0.9729 |             0.7696 |             183.0 с |
| Qwen3-VL-4B GPU 0 |   0.5869 |   0.7261 |             0.5853 |             172.5 с |

Время не включает скачивание и загрузку моделей. Пиковая память, выделенная PyTorch
для Qwen3, — 8.40 GiB; память процесса и резерв allocator могут быть больше.
Сравнение скорости на разных устройствах не является сравнением эффективности
архитектур. Выбран Qwen3 как более качественный из проверенных вариантов, CPU-вариант
оставлен для работы без GPU. Высокий CER означает, что прототип ещё не пригоден для
достоверного автоматического внесения ценников в БД. Первоначальные Qwen2.5-3B и
Qwen3 со структурированным запросом давали галлюцинации/повторы; их smoke-результаты
также сохранены. Итоговый запрос просит только видимый текст.

Отдельный интеграционный запуск `ocr_pipeline_qwen3` обработал по одному кропу из
каждого из пяти видео через настоящий `ocr_inputs.jsonl`, без эталонного текста.
GPU 0 после завершения освобождена.

Новый модуль `lenta_price_tag_scanner.text_prototype` принимает папку изображений,
одно изображение или `ocr_inputs.jsonl` из этапа нарезки. Выдаёт `predictions.jsonl`,
`summary.json`, конфигурацию и при наличии эталонов `evaluation.json`.
При передаче manifest исходное наблюдение (видео, timestamp, bbox) сохраняется
в `source_observation`. Эталонная строка читается только после инференса и не подаётся
модели. Два интеграционных теста проверяют этот интерфейс и границы путей manifest.

Режим `easyocr` работает на CPU, режим `qwen` использует Qwen3-VL-4B-Instruct на GPU.
VLM запускается без дообучения, с детерминированным декодированием и ограничением
повторений. Модель всё ещё может ошибаться и выдумывать отдельные символы. Выход —
сырой текст, а не достоверная запись о товаре. База товаров не подменяет распознанный
текст; она может подключаться отдельным этапом сопоставления в существующем CPU pipeline.

```bash
poetry install --with ocr,vlm
# Ваши размеченные кропы: поворот на 90 градусов против часовой стрелки.
poetry run python -m lenta_price_tag_scanner.text_prototype backend=qwen device=cuda source=../ocr_dataset_all_crops/ocr_dataset_all_crops/images labels=../ocr_dataset_all_crops/ocr_dataset_all_crops/labels output=data/ocr_new_run
# Интеграция с нарезкой видео; labels по умолчанию null.
poetry run python -m lenta_price_tag_scanner.text_prototype backend=qwen device=cuda crop_manifest=data/ocr_ready/ocr_inputs.jsonl output=data/ocr_from_video
# На CPU:
poetry run python -m lenta_price_tag_scanner.text_prototype backend=easyocr device=cpu source=path/to/crops rotation_ccw=0 output=data/ocr_cpu_new
```

Пути разрешаются относительно текущего каталога. Для других камер задайте реальный
`rotation_ccw` (0, 90, 180, 270). Выходная папка должна быть новой. Для сервера перед
запуском выполните `source environment.sh` из `/home/ozon_hack/lenta-ml-system`, затем
`export CUDA_VISIBLE_DEVICES=0`, перейдите в `project` и используйте `../.venv/bin/python`.
Зависимости и кеши на сервере находятся внутри выделенной папки. GPU 1 не используется.

OCR-набор содержит 294 пары PNG/TXT из 5 видео, 107 track-групп; служебные checkpoint
папки исключены. Это полные транскрипции ценников без bounding boxes строк. Дообучение
OCR в этой проверке не выполнялось. Для будущего обучения нужен split по видео/track,
а для построчного recognizer дополнительно нужна разметка строк. Некоторые эталоны
содержат невидимую из-за обрезки часть названия и артефакты форматирования чисел.
CER/WER после нормализации регистра и пробелов измеряют весь текст, включая порядок,
и не эквивалентны точности извлечения цены или артикула.

Модель и настройки предварительно проверялись на первом кропе каждого видео (5 штук).
Эти 5 примеров нельзя считать независимой оценкой выбранного решения; отдельные
метрики остальных 289 сохраняются в итоговом сравнении. Это один набор видео, не
доказательство переносимости на другие магазины.

Источники моделей: [Qwen3-VL-4B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-4B-Instruct),
[EasyOCR](https://www.jaided.ai/easyocr/documentation/).
